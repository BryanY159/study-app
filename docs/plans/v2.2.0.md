# Plan and record: release v2.2.0 (mock results by section)

Status: **built, `v2.2.0` prepared locally, not tagged or pushed.** This is item D10 of
[`v2.1.0.md`](v2.1.0.md). Starting point: `main` at `v2.1.0` (`7420204`).

## What changed
1. **Results screen.** If the pack has `examBlueprint.sections`, the first card shows a score per
   section under the overall score ("First season: 7 / 11, 64%"). The weakest section (lowest
   percentage, first on a tie; none if all tie or fewer than two sections have questions) is tinted
   and labelled "Weakest" (not colour alone). Each section has a "Drill this section" button:
   `#/drill?topics=<every topic of the section's modules>`, which drill setup already preselects
   (and opens the tree path to).
2. **History.** `submitMock` saves `sectionScores: [{ name, correct, total }]` on the session. It is
   an optional field in the same document version, so older apps and data are unaffected. Home's
   recent sessions and the History & data list show it under the session. Sessions without saved
   scores (mocks taken in v2.1.0) are scored from the pack when their results are opened.
3. **No sections.** No section block, no new session field, same results screen as before (tested).

## Decisions made (defaults)
- The scores are matched to the pack's sections by **name** for the drill button, so a saved score
  whose section was renamed in a later pack shows its numbers but no drill button.
- A section with no questions in the mock (an unfilled section) shows "0 / 0, 0%".
- No `@study/pack` contract change (nothing new exported from `src/pack` or `src/engine/public.ts`),
  so the content repo needs nothing for v2.2.0 except bumping the tag if it wants the new app.
