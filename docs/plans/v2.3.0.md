# Plan and record: release v2.3.0 (study-question bank)

Status: **built, `v2.3.0` prepared locally, not tagged or pushed.** Starting point: `main` at
`b28f508` (v2.2.0 plus the local release gate).

## What changed
1. **Five options.** `single` questions may have options A–E. The schema already allowed 2–6 options;
   the work was making every screen cope. The drill, mock and results screens show option E (with the
   student's choice and the correct answer marked), the keys A–E and 1–5 answer, and the key hint
   ("A–E (or 1–5)") follows the question's last option.
2. **Origin `study-bank`.** New value in `QUESTION_ORIGINS`. Such a question shows an
   "Instructor's study bank" badge next to the topic chip in the drill, the mock, the results review
   and the Flags screen (all use `QuestionMeta`).
3. **Sections by origin.** `examBlueprint.sections` entries may name `origins` instead of `groupIds` or
   `moduleIds` (exactly one of the three). A question counts toward one section only, and an origin
   section takes precedence over a group or module section (`sectionIndexOf`). The mock builder and
   the results scoring share it. The "modules in no section" warning ignores modules whose
   unsectioned questions are all claimed by an origin section. On the results screen an origin
   section's "Drill this section" opens the study-bank drill.
4. **"Not found in sources" notice.** A question's optional `note` shows as a notice above the options
   and their explanations (drill feedback, results review, Flags).
5. **Study bank on Home.** When the pack has bank questions, a tile shows "N / M worked through"
   (bank questions answered at least once) and a "Drill study bank" button (`#/drill?filter=bank`).
   Drill setup gains a "Study bank only" filter, shown only when the pack has bank questions.
6. **Flag reason "Ask at office hours"** (`office-hours`). The Flags screen has a reason picker next to
   the export button, so the JSON and Markdown exports can hold only that reason.

## `@study/pack` contract: what the content repo must change
Everything is additive, so older packs still validate. Tag `v2.3.0`, then in the content repo:
- bump the pinned tag to `v2.3.0` (`github:BryanY159/study-app#v2.3.0`);
- **its validator's option-count rule needs work for 4–5 options.** `--single4` (and the per-pack
  `rules.optionCount` in `pipeline/pack-config.ts`) require *exactly* N options for every question, so a
  pack that mixes 4- and 5-option questions cannot pass today. It can be relaxed per pack by
  changing the config, but a range (4–5) or a per-origin rule needs a small change to
  `pipeline/validate.ts` and `PackConfigSchema` (for example `optionCount: number | [min, max]` plus
  an optional per-origin override). That repo is read-only from here, so it is not done in this release;
- if the study bank should be a mock section, add an `origins: ["study-bank"]` section to the pack
  config's blueprint and adjust the other counts so they still add up to `questionCount`.

## Decisions made (defaults)
- **Flags data version not bumped.** `office-hours` is a new value in the flag reason enum. An older
  app (≤ v2.2.0) reading a flags document that holds one would fail to parse that document, so the
  new reason should not be used until every device has v2.3.0. Bumping `FLAGS_VERSION` would make
  older apps leave the document untouched (newer-version protection) instead; it is a small change if
  you prefer that. Packs that use `office-hours` as a pre-flag reason are also v2.3.0 only.
- "Worked through" counts a bank question once it has any attempt (not only correct ones).
- Only `study-bank` has a drill filter and a Home tile; `generated` and `course-practice` origins can be
  used in `origins` sections but have no drill filter.
- Option keys F and beyond: the schema still allows up to 6 options, but F is the flag key during a
  drill, so options past E cannot be answered by keyboard there (unchanged).
