# Study app

A small, offline-friendly quiz engine. It runs drills and timed mock exams, gives
feedback with an explanation for every option, tracks progress by topic, and lets
you flag questions. It is subject-agnostic: **all study material arrives as a
content pack (a JSON file) that you import into the app.**

Live site: https://bryany159.github.io/study-app/

## Privacy model

- **This repository and the hosted site contain no study content.** The only pack
  in the repo is a synthetic test fixture, [`test/fixtures/sample-pack.json`](test/fixtures/sample-pack.json),
  about an invented subject.
- Real packs live elsewhere (a private repo). On each device, you open the site and
  import a pack with **History & data → Import pack…**. The pack is stored in that
  browser only.
- A CI leak guard ([`scripts/leak-guard.ts`](scripts/leak-guard.ts)) fails the build if a pack file,
  a non-fixture pack ID, a large file, or a slide/transcript/image file type appears.

## Using it

1. Open the site in Chrome, Edge or Safari. **Install it** to use it offline: on
   iPhone/iPad, Safari → Share → Add to Home Screen; on a laptop, the install icon in
   Chrome or Edge. The **Install help** page (History & data, or More on a phone)
   shows the steps for your device.
2. On the welcome screen (or **History & data → Import pack…**) choose a pack `.json` file.
3. Use **Cards** for flashcards (spaced repetition, five boxes, capped so every card
   comes round before the exam), **Drill** to practise by topic, or **Mock exam** for a
   timed run. After a wrong drill answer the app offers the related cards.
4. Progress and flags are saved on this device (IndexedDB). To back them up or use
   another device, **History & data → Export sync file** saves one file (on an
   iPhone or iPad it opens the Share sheet). On the other device, **Import sync
   file…** with **Merge** adds what's new; **Replace** makes that device's data
   the file's (a safety copy is saved first). Flashcard progress travels in the same
   file. Backups from v1.4 and sync files from v1.5 import the same way.
5. Home shows a gentle reminder when this device hasn't exported for a few days.

There is no automatic sync and no account: the sync file is the only way data
leaves a device. When a new version is deployed, an installed app shows a
"new version" banner on Home and never reloads in the middle of a session.

The page `spike/storage.html` is a standalone test page for checking whether a
home-screen app on iOS keeps its saved data (see [`spike/ios-storage.md`](spike/ios-storage.md)).

## Development

Requires Node 24.

```bash
npm ci
npm run dev        # Vite dev server on http://localhost:5173
npm run typecheck
npm test           # Vitest unit tests
npm run e2e        # builds, then Playwright against the served build
npx tsx test/makeV14Backup.ts  # rebuild the v1.4-format backup fixture
npm run build      # dist/index.html: one self-contained file
npm run leak-guard # add `-- --dist` to also check the build
```

Tests never use real content: they use the sample pack or packs generated by
[`test/makePack.ts`](test/makePack.ts).

## Content packs

The pack format is defined in one place, [`src/pack/schema.ts`](src/pack/schema.ts) (Zod), with
cross-reference checks in [`src/pack/checks.ts`](src/pack/checks.ts). The app runs both on every
import. A summary is in [`docs/architecture.md`](docs/architecture.md#content-packs).

This repo's root package is published (by git tag, not to npm) as **`@study/pack`**,
so content repos validate their packs with exactly the app's rules:

```jsonc
// package.json in a content repo
"dependencies": { "@study/pack": "github:BryanY159/study-app#v2.0.0" }
```

```ts
import { parsePack } from '@study/pack';          // schema + checks
import { assembleMock, nextState } from '@study/pack/engine'; // pure engine helpers, incl. the card scheduler
```

## Releases

Pushing a tag `vX.Y.Z` runs CI (leak guard, typecheck, unit, e2e, build) and
deploys `dist/` to GitHub Pages. Pushes to `main` and pull requests run the same
checks without deploying. A tag is also a `@study/pack` version, so bump it when
the pack format changes.
